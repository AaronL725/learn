# Learn · Codex + Obsidian

This skill is portable. The project where it is invoked is the working directory and, normally, the Obsidian vault. Never use the skill installation directory as the output directory. Keep foundational truths and motivated discovery at the center of teaching, and preserve the question, feedback and explicit continuation contract.

For a learning/explanation request, read `references/teach.md` in full and use its adaptive probe → plan → teach workflow. Reply in the learner's language. Read `references/knowledge-and-activities.md` on activation: recall relevant personal evidence and project activities before repeating diagnostics or starting a new note. Keep the two teaching principles and per-node motivate → establish → connect → quiz-check loop. Reuse a valid agreed plan and relevant evidence; clarify only what the current goal actually needs.

Teach whatever the learner requests. Do not turn personal memory into an autonomous curriculum, future-topic recommendations, scheduled review or unsolicited check-ins. A new subject gets a separate project; related knowledge can be reused across projects. Let the learner choose when to change topics or notes. Suggest a split when a note becomes unwieldy, then wait for the choice. English filenames do not determine the language of titles, notes or replies.

The personal Atlas defaults to `~/Documents/Knowledge Atlas`, independent of the skill and project. Its editable Markdown contains the learner's profile and concept network; raw evidence remains distinct from interpretations. Record self-reports as self-reports, read optional quiz reasoning, and preserve contradictory evidence. A correct selection is not proof of correct reasoning. The parent teacher curates memory; researcher and maker agents keep their existing roles.

## Portable installation and project binding

Resolve `SKILL_DIR` from this SKILL.md's actual location; all resource paths in this document are relative to that directory. Do not assume it is inside the project or at a particular home path. Read `references/installation-and-relocation.md` for installation, relocation or a new project.

Before the first lesson in a project, run `node "<SKILL_DIR>/scripts/setup.mjs" --project "<PROJECT_DIR>"`. This installs the bundled renderer dependencies at the skill location and generates only the learning-specific project configuration and role templates. Restart/resume Codex, trust the project and review the changed hooks through `/hooks`; do not request unrelated configuration changes. Re-run after moving the skill. With unchanged paths and working hooks, do not reinstall on every lesson.

Run runtime scripts with the current directory set to PROJECT_DIR. Topic notes, `.learn/` activity/session state and pending memory writes, and `viz/` images belong to that project. Existing `learning-log.md` notes remain usable; new projects create a meaningful topic note when the requested topic is known. The skill directory stores only code, references, templates and renderer dependencies. Link any existing note via md_log, including absolute paths outside the project; when the linked note is in a different Obsidian vault, put the published images in that vault or use resolvable Markdown image paths rather than assuming a filename-only embed will resolve.

Read `references/teach.md` in full for every teaching request. Use its complete body as the teaching contract, with the interface mappings below. Before the first graded or ungraded question, also read `references/native-question-workflow.md`, including all original tool guidelines. For a lesson visual read `references/visualize.md`. The original role templates are in `agents/*.toml`; setup registers copies under the invoking project's `.codex/agents/`.

## Native Codex mapping

- `quiz` in the teaching workflow maps to **native `request_user_input` plus the local deterministic grader**, not an MCP/browser question. Read `references/native-question-workflow.md` before the first quiz. Prepare once with `node "<SKILL_DIR>/scripts/quiz.mjs" prepare <JSON-file>` (question, options with stable values, correctAnswer, explanation, sessionId; learning metadata comes from the active activity and can specify conceptIds/scope; default shuffle, multiSelect supported). Invoke exactly the returned `request` through native request_user_input, one question per call. No recommended/correct hints. Read `node "<SKILL_DIR>/scripts/quiz.mjs" result <id> <sessionId>` immediately after submission; never judge it from memory. Show the returned feedback and correct answer, then use a SECOND native question offering Continue / Pause, with feedback in its question. Do not teach further until Continue is explicitly selected. Interpret notes and diagnose distractors before updating concept interpretations; record evidence and checkpoint progress as described in `references/knowledge-and-activities.md`. If `memorySync` is pending, explain briefly that local feedback is complete and Atlas synchronization is queued; retry sync without making the learner re-answer. Empty, timed-out, cancelled or invalid responses are NEVER answers or continuation permission: re-ask the SAME id/request/order, or honor an explicit stop. Do not re-prepare or reshuffle on retry.
- Native CLI 0.162.1 supports scrolling arbitrary-length single-choice lists (the schema's 2–3 is guidance, not validation). Keep every real option plus “I don't know”. If another runtime enforces 2–3 options, prepare with `--compact`: show the entire unchanged numbered list and collect the chosen number through Tab notes. Multi-select always uses the same entire list plus Submit / I don't know, with the FULL index set on the first notes line and optional reasoning on later lines. Never split a multi-select quiz into separately graded yes/no questions. Exact-set grading and unknown exclusivity remain mandatory. Automatic None of the above is not an extra gradable distractor; accept only valid original option indices, otherwise re-ask. Pressing any key disables Default-mode's ~120-second idle auto-resolution; Plan mode blocks without that timer. Explain this briefly before the first question, and never score a timeout.
- `ask_user_question` means an ungraded preference/direction/checkpoint, preferably native request_user_input. Direct single-choice questions support automatic Other and Tab notes; use the local prepare adapter with name="ask_user_question" for free text, multi-select or combined original choices + custom Other, preserving all modes. Native calls and their notes are logged automatically. Free text goes in Tab notes; multi-select notes first line contains the full index set, optionally `Other: <custom answer>` on another line. A cancelled question is not an answer.
- `researcher` means the native custom agent `.codex/agents/researcher.toml`. Send a self-contained task; search and actually read sources, return citations and gaps, then close the child if that native API exists; otherwise confirm completed and interrupt only if still running. Verify uncertain claims before teaching, and map the field with this researcher in Phase 2. If the runtime only exposes collaboration.spawn_agent, read the role TOML and include its developer_instructions in the child task. Do not silently replace required research with memory. Without subagents the main session can teach and verify sources directly; disclose that dedicated research and maker agents are unavailable. Never substitute memory for source verification or publish an uninspected visual.
- Visuals: read `references/visualize.md`, use native makers, keep write/edit/render/inspect/publish and unique PNG embeds. Makers inherit the local Codex model/provider, replacing Pi-only model IDs. Each managed diagram has its own session ID; always pass it to edit/render.
- Logs: the native SessionStart hook restores this session's previous link or an existing legacy `learning-log.md`; a fresh project can start unlinked. On learn activation, `study.mjs open` creates or resumes the chosen topic note. Persist checkpoints during teaching and at pauses; `study.mjs switch` flushes the old note and starts the chosen continuation at the current transcript position. Markdown, `$...$`, display `$$` and Mermaid fences pass through verbatim to Obsidian. Quiz questions are logged in displayed shuffled order before response; answers/notes/feedback only after submit. Reasoning traces and operational tools are excluded.
- User commands `/md-log <existing-note.md>` and `/md-unlog` are implemented by MCP `md_log` / `md_unlog` with the current sessionId. Codex CLI does not register third-party slash commands, so type them as ordinary chat text (or use natural language to link/unlink); perform the operation, do not merely explain it. Explicit md_log defaults to backfill; optional mode="forward" starts at the current position. Backfill follows active-branch rollbacks and exact paginated history prefixes (including zstd archives), preserves existing note content and deduplicates resumed/inherited prefixes. Pass the current sessionId to `result <id> <sessionId>` so forked pending answers stay isolated from the parent.
- If no SessionStart context is present, run the per-project setup and tell the learner that the generated local hooks need to be enabled/trusted via `/hooks`, then restart/resume the session; do not invent a session ID. Never treat intentional `/md-unlog` as a teaching prohibition. The upstream optional-logging mode remains possible, but live Obsidian synchronization requires these hooks. For configuration/test tasks, do not run the teaching skill or open questions to the learner.

Do not add model API keys, Pi, tmux or a second agent framework.
